# SolomonSeal

> Печать Соломона — древний символ договора, который связывал джиннов, не позволяя им действовать по собственному произволу. **SolomonSeal** — это прозрачный оркестратор для работы с LLM, который даёт вам такую же власть над нейросетевыми моделями: вы точно знаете, что им передано, что они могут сделать и во сколько токенов это обойдётся.

## Идея проекта

Современные AI coding tools (Cursor, Windsurf, OpenCode и другие) часто работают как «чёрный ящик»:

- даже простой вопрос в режиме Ask может незаметно тянуть за собой десятки tool calls и системных промптов;
- пользователь не видит, что реально отправляется в модель;
- агентность включена по умолчанию там, где нужен просто диалог;
- стоимость по токенам растёт непрозрачно и непредсказуемо;
- модель может «интерпретировать» задачу по-своему, выходя за рамки того, что от неё просили.

**SolomonSeal** решает эту проблему буквально — как печать, которая связывает джинна договором:

- **Ask mode = ноль скрытых tool calls.** Модель физически не получает описание инструментов, если пользователь не запросил agent-режим.
- **Agent mode = видимый цикл.** Каждый вызов инструмента — `→ tool_call` / `← result` — отображается в UI шаг за шагом, а не постфактум.
- **Полная прозрачность контекста.** Debug-панель показывает system prompt, состав payload, оценку токенов, raw JSON запроса и ответа — до отправки и после.
- **Явные границы допустимых действий.** Режимы Ask / Plan / Build задают жёсткий периметр разрешений (read-only, write, exec) — модель не может выйти за пределы того, что разрешено в текущем режиме.

## Ключевые возможности

- **Три режима работы**: `Ask` (диалог без агента), `Plan` (агент только читает и анализирует), `Build` (полноценный coding agent с write/exec-инструментами).
- **Детерминированная сборка контекста без LLM-оркестратора** — `DeterministicContextAssembler` собирает контекст напрямую из SQLite-индекса (символы + full-text search), без единого дополнительного вызова модели.
- **Multi-project sessions** — можно подключить несколько проектов (`backend`, `frontend` и т.д.) в одну сессию и делать сквозной анализ через alias-адресацию файлов.
- **Единый OpenAI-compatible клиент** — работает с LiteLLM, Ollama и любым совместимым эндпоинтом без vendor lock-in.
- **Approve/deny для опасных действий** — запись файлов и выполнение команд подтверждаются явно, с таймаутами и потоковым выводом.
- **Два интерфейса** — desktop-приложение на JavaFX и консольный CLI/TUI поверх одного и того же core-слоя.

                               │

      │ Built-in Tools   │           │ External Systems   │

Ключевой принцип: UI не содержит бизнес-логику агента — это только клиент к core-слою. Это позволяет переиспользовать одну и ту же логику в JavaFX, CLI и в будущем в HTTP API.

## Режимы работы

| Режим | Назначение | Доступные инструменты |
|---|---|---|
| **Ask** | Быстрый прозрачный диалог, минимальный контекст | Инструменты отключены, агентный цикл не запускается |
| **Plan** | Агентный анализ кодовой базы без изменений | read / grep / glob / list_tree — запись и exec запрещены |
| **Build** | Полноценный coding agent | read / write / edit / exec (с подтверждением) |

## Профили контекста

Пользователь явно выбирает, что отправляется в модель:

- `MINIMAL` — только system prompt + вопрос;
- `SELECTION` — вопрос + выделенный фрагмент;
- `CURRENT_FILE` — вопрос + текущий файл;
- `FILE_SET` — вопрос + выбранные файлы;
- `DIFF` — вопрос + git diff/status;
- `PROJECT_SUMMARY` / `MULTI_PROJECT` — вопрос + карта одного или нескольких проектов.

Для каждого запроса в debug-панели видно: какие куски попали в payload, оценку размера в токенах, список приложенных tools и используемый system prompt.

## Инструменты (agent tools)

Первая очередь встроенных инструментов реализована в чистой Java, без внешних зависимостей от shell-утилит:

- `ReadFileTool`, `WriteFileTool`, `EditFileTool`, `DeleteFileTool`
- `GrepTool`, `GlobTool`, `ListTreeTool`
- `FindSymbolTool`, `SearchCodeTool` — быстрый поиск по SQLite-индексу проекта
- `BashTool` — мост к внешним dev-командам (`mvn test`, `npm test` и т.д.) с обязательным approve/deny и таймаутами
- `WebFetchTool` — получение содержимого веб-страниц

## Технологический стек

- **Java 21**, модульная система (`module-info.java`)
- **JavaFX 21** — desktop UI
- **Jackson** — сериализация JSON
- **SQLite (xerial jdbc)** — индекс проекта (символы, FTS)
- **JavaParser** — AST-анализ Java-кода для индексатора
- **SLF4J + Logback** — логирование
- **JUnit 5** — тестирование

## Быстрый старт

```bash
# desktop UI
./gradlew run

# CLI (в разработке)
solomonseal
solomonseal ask "объясни этот код"
solomonseal ask --file src/Main.java "что тут улучшить"
solomonseal agent --project backend --project frontend "проверь интеграцию логина"
```

## Статус проекта

Проект находится в активной разработке (MVP). Реализовано: единый core-слой, session management, OpenAI-compatible LLM client, ask mode, context profiles, debug/payload panel, JavaFX UI, базовые agent tools, agent loop для plan/build режимов, approve/deny для команд.

В планах: CLI/TUI-режим, sub-agents, MCP client, более глубокая multi-project интеграция.

## Философия проекта

Не строить ещё один тяжёлый black-box агент. Строить прозрачный, модульный, опционально агентный инструмент, ориентированный на контроль контекста и стоимости — как печать Соломона держит джинна в рамках договора, а не позволяет ему действовать по собственному усмотрению.
